Implementation Specification

### [1] Problem Interface
The program reads from standard input and writes to standard output as follows:
- First, it reads one scalar token (an integer) `n`, representing the number of operations.
- Then, it reads one fixed-length token block of `n` integers, denoted `x[1..n]`, where `x[i]` is the integer added in the i-th operation (1-based operation index).
- The input layout is exactly two lines: the first line contains one integer `n`, the second line contains `n` space-separated integers `x[1], x[2], ..., x[n]`.
- After each of the `n` operations (i.e., after adding `x[1]`, then after adding `x[2]`, ..., up to after adding `x[n]`), the program outputs one integer per line on standard output, for a total of `n` lines.
- The k-th output line (1 ≤ k ≤ n) is the bitwise XOR of all indices `i` (1-based) such that `i` is a suffix maximum position in the current array `a` of length `k`, where `a[i]` is the value added at operation `i`.

### [2] Formal Definitions
Let `a[1..k]` be the array after `k` operations, where `a[i] = x[i]` for `1 ≤ i ≤ k`.  
A position `i` (1 ≤ i ≤ k) is a **suffix maximum position** if and only if:  
∀ j with `i < j ≤ k`, `a[i] > a[j]`.  
Let `S_k ⊆ {1, 2, ..., k}` be the set of all suffix maximum positions in `a[1..k]`.  
The required output after the k-th operation is:  
`ans_k = ⨁_{i ∈ S_k} i`,  
where `⨁` denotes bitwise XOR.

### [3] Required Complexity
Given `1 ≤ n ≤ 10^6` and `x_i < 2^64`, the algorithm must run in O(n) time and O(n) space, or better (e.g., O(n) time and O(1) extra space beyond input storage). A naive O(n^2) approach (checking all suffixes for each k) is infeasible.

### [4] Maintained State
- `stack`: a stack (LIFO) storing indices `i` (1-based) of elements that are currently suffix maxima. The stack is maintained in **strictly decreasing order of values** `a[stack[t]]`, with the top of the stack (last element) being the index of the global maximum (i.e., the leftmost suffix maximum).  
- `ans`: an integer storing the current XOR of all indices in `stack`.  
- `x[1..n]`: the already-parsed input array of added values (1-based indexing for positions).  
- `a[1..k]` is implicitly `x[1..k]` after `k` operations.

### [5] Invariants
After processing `k` operations (i.e., after handling `x[1..k]`):
- `stack` contains exactly the set `S_k` of suffix maximum positions (1-based indices) in `a[1..k]`.
- The stack is ordered such that `stack[1] < stack[2] < ... < stack[t]` (increasing indices) and `a[stack[1]] > a[stack[2]] > ... > a[stack[t]]` (strictly decreasing values).
- `ans = ⨁_{i ∈ stack} i`.
- The top of the stack (last element) is the index of the global maximum of `a[1..k]`.

### [6] Per-Operation Update Rules
Process operations `k = 1` to `n` in order:
1. Append `x[k]` to the array (implicitly, `a[k] = x[k]`).
2. While `stack` is non-empty and `a[stack.top()] ≤ x[k]`:
   - Let `j = stack.pop()`.
   - Update `ans = ans XOR j`.
3. Push `k` onto `stack`.
4. Update `ans = ans XOR k`.
5. Output `ans`.

Explanation of step 2:  
- Any element `j` in the current stack with `a[j] ≤ x[k]` cannot be a suffix maximum in `a[1..k]`, because `j < k` and `a[j] ≤ x[k] = a[k]`, violating the condition `a[j] > a[k]`.  
- Since the stack is strictly decreasing in values, once `a[stack.top()] > x[k]` is found, all remaining elements in the stack satisfy `a[stack[i]] > a[stack.top()] > x[k]`, so they remain suffix maxima.  
- The new element `k` is always a suffix maximum (vacuously, as there is no `j > k` yet), and it becomes the new leftmost suffix maximum (smallest index in `S_k`), with value `x[k]` that is strictly greater than all values of elements popped.

### [7] Output Rule
After each operation `k` (1 ≤ k ≤ n), output the current value of `ans`, which is the XOR of all indices in `stack`. The output is `n` lines, the k-th line being `ans` after step 4 above.

### [8] Edge Cases and Consistency Checks
- **Empty stack handling**: When `stack` is empty before step 2 (only at `k=1`), the while loop is skipped, `k=1` is pushed, and `ans = 0 XOR 1 = 1`, matching sample output first line.
- **Equality case**: The condition `a[stack.top()] ≤ x[k]` uses non-strict inequality (`≤`), so equal values cause the old index to be popped. This is correct because the definition requires `a_i > a_j` for all `j > i`; if `a_i = a_j`, then `i` is not a suffix maximum.
- **Single element**: For `k=1`, `S_1 = {1}`, so `ans = 1`.
- **Strictly decreasing input**: If `x[1] > x[2] > ... > x[n]`, then `stack = [1, 2, ..., k]` after `k` operations, and `ans = 1 XOR 2 XOR ... XOR k`.
- **Strictly increasing input**: If `x[1] < x[2] < ... < x[n]`, then after `k` operations, `stack = [k]`, so `ans = k`.
- **Parsing-unit consistency**: The input must be parsed as one fixed-length block of `n` integers on the second line; interpreting it as `n` separate scalar reads per line (e.g., one integer per line) would be incorrect.
- **Indexing convention**: All indices stored in `stack` and used in `ans` are 1-based, matching the problem statement. No conversion to 0-based indexing is performed at any stage.
- **Wrong interpretations to avoid**:
  - Using `≥` instead of `>` in the suffix maximum condition would incorrectly include equal values.
  - Using `a[stack.top()] < x[k]` (strict) in the while condition would fail to pop equal values, violating the `>` requirement.
  - Storing values instead of indices in the stack would lose position information needed for XOR.
  - Outputting the XOR of values instead of indices would be incorrect.
  - Using 0-based indexing internally and converting at output would introduce off-by-one errors.

Note: The main function must be defined and called at the end of the code to ensure execution and output.
